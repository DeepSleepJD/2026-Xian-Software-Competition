# P2 经济层：顺路任务 90 分 + 冰鉴阈值管理

## 背景

P1 完成后对打官方 demo 100% 交付但 428 vs 496，差距全在任务分。
规则调研 + 实测数据 + 设计草案已归档于 `docs/P2经济层开发准备.md`（本 PRD 的唯一上游依据）。

## 需求

新增 `client/lychee/strategy/economy.py`（EconomyStrategy），冻结契约不动（只读 GameState、产 Intent）：

1. **顺路任务**：NORMAL 阶段 && 未验核 && task_score < 90 时，贪心选
   value/(绕路增量帧+1) 最大的可达任务，赶路 → 到点发 CLAIM_TASK。
   候选过滤：active 未完成、无对方归属/保护、round+路程+读条 ≤ expireRound。
2. **冰鉴领取**：CLAIM_RESOURCE 纳入同一贪心目标池（value≈18），顺路才取。
3. **冰鉴使用**：停靠时 freshness ≤ 下一个十位阈值+2 即 USE_RESOURCE；
   出发上长边前预判途中跨阈值则提前用。
4. **防守细节**：读条/移动中 propose []；CLAIM 被拒下帧重试或换目标；
   窗口争夺弃权（不出牌）；固定处理站点未处理完不抢 MOVE（让位 delivery 的 PROCESS）。
5. 优先级：冰鉴使用 120 > 任务/资源 110 > delivery 100（arbiter 同类别只放行最高）。

## 验收

- 单测绿（合成小图驱动 economy 状态机），原 53 例不回归
- `tools/run_match.py` 对局：任务分 ≥90、总分 650-700、仍 100% 交付
- 流程：跳过 trellis-check，里程碑粒度 commit（负责人定的快速迭代规矩）

## 结果（2026-07-02 完成）

- 全部达标：**702 分**（demo 458）、任务 raw 90（csv 125 含里程碑）、100% 交付、
  单测 82 例绿。seed 20260618 / 12345 结果一致，零罚分零超预算
- 设计对草案的两处偏离（实测两局回归驱动，理由见 economy.py 模块注释）：
  1. 估值从 value/(cost+1) 改为**净值 + 一步前瞻**（比值制漏 90 里程碑、
     单步贪心永不领冰鉴）
  2. 新增**无候选时原地 WAIT 蹲守**（任务刷新后才进 feed，走过头回不了头）；
     本seed 实际 0 次触发（前瞻改走官道任务带后 172 帧即拿满）
- 涌现行为：前瞻自己发现官道沿线（S03/S06/S07）任务+冰鉴更密，
  比草案预设的水路顺路方案更快拿满（172 帧 vs 413 帧）
