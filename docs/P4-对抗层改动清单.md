## 1. 规则依据速查(实施必读,数值已核对任务书原文)

### 1.1 设卡(任务书 6.2)
- `SET_GUARD`:只能设在**主车队当前所在节点**;S15 禁设。处理 4 帧,完成后**下一帧**开始拦截。
- 防守值 = `min(上限, 2 + 额外好果×2)`,额外好果 `extraGoodFruit` ∈ {0,1,2}。上限:普通 6 / **关键关隘 7(成本 1 好果)** / 宫门 S14 4(成本 1 好果) / 有路障节点 5。
- 每队同时最多 **2 个**有效设卡;超出移除本队最早的。
- 风化:每 30 帧 -1(关键关隘且完成时防守值≥4:首次 45 帧,后续每 30 帧)。降到 0 即失效。

### 1.2 攻坚破卡(任务书 6.3.1)——被卡时的首选反制
- `BREAK_GUARD`:主车队动作,**目标必须是当前所在节点的相邻节点**,该节点有敌方有效设卡。
- 投入:好果 ≤2(每篓 **2 攻坚值**)+ 坏果 ≤2(每篓 **3 攻坚值**),上限 10;宫宴冲刺期可附带 `rushTactic: BREAK_ORDER` 额外 +3(占终局急策额度,整局 1 次)。
- **无处理帧数**——当帧结算。攻坚值 ≥ 当前防守值 → 设卡清零(车队留在原地,下帧 MOVE 进入);不足 → 防守值减攻坚值、我方休整 5 帧后可再攻。
- 果品投入成功失败都不返还。坏果本来不计分,**是免费弹药**;好果每篓 ≈1.8 分(对手交付好果分 163/91篓),两篓 ≈3.6 分 vs 被钉 190 帧,必换。
- 数学:defense 6 → `2坏+0好=6` 一击破;defense 7 → `2坏+1好=8` 一击破。

### 1.3 关键陷阱:MOVING 状态不能攻坚(任务书 8.2)
`MOVING` 状态只允许 `WAIT` / 继续 `MOVE` / 马类资源 / 疾行令,**且禁止原路折返**。match3 就是半路(E17 67%)被后设的卡冻死、无解等风化。→ **必须做上边前预判**(见改动 C-2)。

### 1.4 强制通行(任务书 6.3.2)——次选,一般劣于攻坚
`FORCED_PASS` 触发 PASS 通行窗口(出牌);胜也要付时间税(关键关隘 `min(50, 15+防守值×5)` 帧),败/平休整。仅当果品耗尽打不动时作备选。

### 1.5 窗口出牌(任务书 5.4)
- 触发后 3 拍,每帧 1 张,胜点多者赢;克制矩阵(行=我方):

| 我 \ 敌 | YAN_DIE | QIANG_XING | XIAN_GONG | BING_ZHENG |
|---|---|---|---|---|
| YAN_DIE(1 文书) | 平 | 胜 | 负 | 负 |
| QIANG_XING(1 马,有马 buff 免费) | 负 | 平 | 胜 | 负 |
| XIAN_GONG(1 好果,需鲜度≥80) | 胜 | 负 | 平 | **胜** |
| BING_ZHENG(1 护卫行动点) | 胜 | 胜 | 负 | 平 |

- 护卫行动点每队 4 点、不恢复、只用于 BING_ZHENG(任务书 3.3.5)。
- 空动作=弃权不计非法;**缺 contestId/card 或未知牌 = 弃权且计 1 次非法**(5.4.2),动作必须带全字段。
- 实测:DeepExpress 全场只出 BING_ZHENG → **鲜度≥80 时 XIAN_GONG 是它的克牌**。
- 平局有休整/冷却惩罚,细则见 5.4.4。

### 1.6 破关悬赏(任务书 6.3.3)——落后方的补偿分
设卡站住 ≥30 帧会生成悬赏(普通 10 / 关键关隘 18);**攻破清零者若当帧公开总分低于设卡方**则得分。我方被卡时必然落后 → 破卡顺带拿悬赏,天然正收益。

### 1.7 动作额度(任务书 4.1)
每帧四类额度互不占用、各 1 个:主车队 / 小分队 / 窗口出牌 / 终局急策。→ 出牌与移动/攻坚同帧不冲突;同类超 1 个 = 全不执行 + 计非法。

### 1.8 协议字段(通信协议.md 动作表,现网已实测)
- `BREAK_GUARD`:`{action, targetNodeId, goodFruit(0-2), badFruit(0-2)[, rushTactic]}`
- `SET_GUARD`:`{action, targetNodeId(=当前节点), extraGoodFruit(0-2)}`
- `WINDOW_CARD`:`{action, contestId, card}`
- 守卫状态在 `inquire.nodes[].guard`:`{active, defense, initialDefense, maxDefense, ownerTeamId, completeRound, ageRound}`(现网直接下发 `active`,client/lychee/state.py 已解析并有 active 兜底推导)。
- 被堵信号:`events[]` 里 `ACTION_REJECTED` 且 `payload.errorCode == "MOVE_BLOCKED_BY_GUARD"`;其余错误码:`PROCESS_REQUIRED`、`OBJECT_BUSY`(节点进程被对手独占)、`TASK_REQUIREMENT_NOT_MET`。

## 2. 改动清单(按优先级;A→D 为 P0,做完才有资格谈别的)

### A. 状态层:对抗信息暴露(`client/lychee/state.py`)
现有 `Guard`/`NodeState.guard`/`Contest`/`Bounty` 数据类已齐,只补访问器与错误码:

1. `ActionResult`/`Event` 补 `errorCode` 解析(事件 `payload.errorCode`;actionResults 若带同名字段一并收)。
2. `GameState` 新增 helper(供策略层用,全部带单测):
   - `my_state() -> str`:我方 `players[].state`(IDLE/MOVING/WAITING/PROCESSING/CONTESTING/RESTING/…)。
   - `enemy_guard_at(node_id) -> Guard | None`:该节点是否有**敌方**有效设卡(`active` 且 `ownerTeamId != 我方 teamId` 且 `defense > 0`)。
   - `blocked_by_guard() -> str | None`:本帧(或近 N 帧)我方是否收到 `MOVE_BLOCKED_BY_GUARD`,返回被堵的目标节点(从我方 `nextNodeId` 推)。
   - `my_open_contests() -> list[Contest]`:我方参与、未 resolved 的窗口(现有 `my_contests` 基础上过滤)。
   - `my_guard_points / my_good / my_bad`:直读字段的便捷属性(已有则复用)。
3. **验收**:用 `looog/game_result (3)/logs/*.jsonl` 逐帧回放(recorder 格式相同),断言 r320 时 `enemy_guard_at("S10").defense == 6`、`blocked_by_guard() == "S10"`。

### B. 新建对抗策略:`client/lychee/strategy/combat.py`(CombatStrategy)

挂进 `main.py`/`strategy/__init__.py` 的策略列表,intent 经现有 arbiter 合并。

**B-1 破卡(最高优先)**
- 触发:交付/经济路径的下一跳节点存在敌方有效设卡,且 `my_state()` ∈ {IDLE, WAITING}(相邻性:下一跳必相邻)。
- 投入解算:`need = guard.defense`;先坏果 `bad = min(2, 我方坏果)`,不足再好果 `good = min(2, ceil((need - 3*bad) / 2))`(注意 good 也 ≤ 我方可支配好果)。`3*bad + 2*good >= need` 则一击破;打不满也打(削防),休整 5 帧后重试(用现有 backoff 机制记 `REST:round+5`)。
- 宫宴冲刺期(`phase`/RUSH_START 事件后)且终局急策未用:攻坚值差 ≤3 时附 `rushTactic: "BREAK_ORDER"`。
- Intent 优先级:**高于 economy 与 delivery 的 MOVE**(被卡时 MOVE 反正会被拒;数值上建议 > delivery.MOVE 的 priority,具体看 `arbiter.py` 现有优先级常量)。
- 悬赏分不需要单独逻辑:破卡即顺带结算(落后时才发分,正好匹配被卡场景)。

**B-2 上边前守卫预判(防 MOVING 陷阱态,规则 1.3)**
- 铁律:**目标节点有敌方有效设卡时禁止提交进入该边的 MOVE**(pathing 返回下一跳后、发 MOVE 前检查)。改为:相邻则直接 B-1 攻坚;不相邻则照常走到相邻节点再攻。
- 简单版威胁规避(本期只做这一条,更复杂的预测放 P2):对手主车队已在我方路径上的 KEY_PASS/PASS/GATE 节点驻留(state 非 MOVING)且我方即将上通往该节点的边、且边行程 > 30 帧 → 在当前节点 `WAIT` 观察 2-3 帧再决策(防"上边后被设卡")。参数化,可关。

**B-3 我方设卡(对称武器)**
- 触发条件(全部满足):
  1. 我方领先于对手的交付进度(比较双方到 S15 的剩余路径帧数,pathing 已能算)且对手未交付;
  2. 我方当前节点在**对手剩余路径的必经点集合**上(用图割点/必经判定,见 C-1),且非 S15;
  3. 我方好果充足(交付底仓阈值以上,建议保留 ≥90 篓时才投 2 好果);每队上限 2 个有效卡,超限不设。
- 动作:`SET_GUARD extraGoodFruit=2`(防守值拉满 6/7);处理 4 帧计入绕路成本,用现有净值框架估值(拦对手 ~180 帧 ≫ 4 帧 + 1-3 好果)。
- 位置偏好:KEY_PASS(上限 7、悬赏冷却对我不利面小)> 普通 PASS;S14 上限只有 4,价值低。

**B-4 窗口出牌**
- 每帧检查 `my_open_contests()`,对每个进行中窗口出 1 张(窗口出牌独立额度,不影响主动作):
  - 该窗口的争夺对象在我方关键路径上(渡口 TRANSFER、PASS 通行、GATE 验核、我方正要领的资源/任务)→ **争**:鲜度≥80 且好果余量足 → `XIAN_GONG`(克 DeepExpress 的 BING_ZHENG);否则护卫行动点>0 → `BING_ZHENG`;都没有 → `ABSTAIN`。
  - 无关对象 → `ABSTAIN`(零成本,不计非法)。
- 严格带全 `contestId` + `card`(缺字段=弃权+计非法,规则 1.5)。
- 行动点预算:4 点全局资源,建议保留 ≥1 点给终局宫门/通行窗口(参数)。

### C. 寻路层:必经点分析(`client/lychee/pathing.py`)
- **C-1** 新增 `choke_nodes(graph, src, dst) -> set[str]`:src→dst 所有简单路径的必经节点(等价:删除该点后 src 到 dst 不连通)。O(V·E) 暴力即可,图只有 15 节点。供 B-2(我方风险)与 B-3(卡对手)双向使用,**禁止硬编码 S10**(会换图)。
- **C-2** 路径代价函数加"敌方设卡惩罚":下一跳节点有敌方有效卡时,该边代价 += 预计破卡帧数(≈1-2 帧)与果品折分;若我方果品不足以破卡,代价 += 剩余风化帧数。让 pathing 在"破卡直行"与"绕行"间自然权衡(多数咽喉无绕行,惩罚小时仍会选直行+攻坚)。

### D. 经济层修复(`client/lychee/strategy/economy.py`)
- **D-1 路线振荡(match4 白耗 80 帧)**:目标承诺 + 迟滞——已在途(非 IDLE)时,新目标净值必须超过当前目标 `HYSTERESIS`(建议 15-25%,调参)才允许换目标;且**禁止选择需要原路折返上一条刚走完的边**的目标,除非净值差 > 一条边的帧成本。加回放单测:match4 r93-134 场景不再折返。
- **D-2 资源领取泛化**:现在只认 ICE_BOX。改为按 `resourceType` 语义表驱动:`ICE_BOX`(保鲜,现逻辑)、`SHORT_HORSE/FAST_HORSE`(加速+让 QIANG_XING 免费)、`PASS_TOKEN/OFFICIAL_PERMIT`(文书:YAN_DIE 成本+验核相关,读任务书 3.3.3)、`INTEL`(读 3.3.4)。**0 绕路(脚下/顺路节点)一律领**;绕路的按现有净值框架估值。马类价值需按现网重估(本地"+1 分判死"结论不可迁移——马 buff 还联动出牌成本)。
- **D-3 天气感知(可后置到 P1 末)**:HOT 期鲜度衰减加速 → ICE 使用阈值前移;HEAVY_RAIN(WATER 区)/MOUNTAIN_FOG(MOUNTAIN 区)按任务书 2.5 的效果表给对应 routeType 边加临时代价。天气有 `forecast` 字段可预判。

### E. 小分队(P2,前面全绿再做)
`SQUAD_SCOUT`(探路 + 加速节点进程的斥候标记,对手用它把 BOARD 7 帧减到 4 帧)、`SQUAD_WEAKEN`(远程削卡,是被半路钉死时**唯一**的反制手段——小分队动作不受主车队 MOVING 限制,读任务书 6.4.3 核实)、`SQUAD_CLEAR`(远程清障)。最小版:被 MOVING 钉死时无脑 `SQUAD_WEAKEN` 目标卡点。

## 4. 硬性约束(违者直接输,改动时不得破坏)

- 每帧必发 action(空 `actions:[]` 也是心跳);`action.round == inquire.round`;500ms/帧内决策(现网 1 帧≈1s,预算宽裕,别在 combat 里写重循环即可)。
- **不写死** playerId/host/port/阵营/地图:S10 等咽喉必须由 `choke_nodes()` 现算;资源、防守值上限、节点类型全部读 `start`/`inquire` 下发。
- 同类动作每帧 ≤1(超 1 = 全不执行 + 计非法);`WINDOW_CARD` 必须带全 `contestId`+`card`。
- 现有 GameState/Intent 契约与 delivery 铁律(60 帧缺动作兜底、交付优先)不得回退。
