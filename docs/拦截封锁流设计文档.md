# 拦截封锁流 设计文档（自包含）

> 目标：把客户端从"送达+顺手对抗"升级为**主动拦截封锁**——抢跑到对手身前的必经节点，
> 在他上边的瞬间设卡把他**冻死在半路**，让他完不成交付（封顶 ~105），我方照常送达（~600）。
> 本文自包含：战略前提 + 规则依据（带行号）+ 现有零件盘点 + 改动清单 + 触发时序 +
> 公式 + 接线点 + 验证方案 + 单测清单 + 回退旋钮 + 风险登记 + 分阶段落地。
>
> 讨论归因：2026-07-03 session（本文档即该 session 对齐结论的落地蓝本）。

## 0. 一句话

**只要不破坏自己的交付死线，就在对手身前的必经节点用"上边瞬间设卡"把他冻在半路；
一到自己的交付死线立即弃拦直冲 S15。** 窗口默认三联献贡。

## 1. 战略前提：为什么"拦截 = 赢"（EV 推导）

得分结构（任务书:72,1228,1337，见 §2）：
- **交付方**：送达基础分 + 好果数量分 + **鲜度品质分（封顶 180）** + 用时分 + 任务分 + 悬赏分 ≈ **600+**。
- **未交付方**：送达/好果/鲜度/用时全为 0，任务分封顶 80、悬赏封顶 25 → **总分上限 ≈105**。

两种打法的 EV：

| 打法 | 我方 | 对手 | 结局 |
|---|---|---|---|
| **不拦**（只送达） | ~600 | 对手晚几帧照样送达 ~600 | 双方都 600，拼任务分/鲜度 = **硬币局**（近期连败即此） |
| **拦截**（冻死对手） | ~600 | 封顶 ~105 | **碾压** |

**结论：拦截把"硬币局"变"碾压局"，EV 摆动数百分，远大于设卡烧的几篓好果。**
所以设卡触发**不设速度闸**（对手等速/更慢也要拦——他能送达就是 ~600），
唯一闸门是：**拦他会不会害我自己破掉交付死线**。破则弃拦直冲。

### 1.1 冻结陷阱：拦截为什么钉得死

规则组合（§2 详列）产生一个**"半路冻结"**形态：

- 对手**已驶上边**（`state=MOVING`）后，我在他目标节点设卡并生效 → 他到达时被卡，
  **停不进节点、冻在边上**。
- `MOVING` 状态**合法动作只有 4 个**：`WAIT`/`MOVE 到当前目标`/马/疾行令（任务书:1286）。
  **强通、攻坚都不在内**，且两者都硬性要求"当前所在节点"（:950/:982）——冻在边上没有当前节点。
- 半路**禁止原路折返**（:1286）。
- ⇒ 冻结的对手**唯一主动出路 = 派小分队削卡**（8 支上限，我可增援对拉）**或干等风化**
  （关隘满防 7 靠风化归零要 `45+6×30≈225` 帧）。

这就是历史上把我方钉 180 帧、现网被 525:0 的那个形态（`docs/P4h`/P4e 尸检）。
**本策略是把这把刀反过来主动用在对手身上。**

关键前提（must be true，见 §6 公式）：
- **P1 时序窗口**：设卡读条 4 帧 + 下一帧生效 ≈ 5 帧；必须在"对手 commit 上边"到"他到达"
  之间塞进这 ≈5 帧。即 detect 当帧他离目标节点还有 ≥ ~6 帧路程。
- **P2 抢跑领先**：我必须先到该节点并站定（camp）。
- **P3 对手会 commit**：聪明镜像对手看到我 camp 在咽喉可能"不上钩"停在上一节点等我走——
  这不救他（见 §1.2）。

### 1.2 对手"不上钩"也救不了他（R2 结论）

单通道上（S09 之后 S10→S14 无绕行，`docs/比赛分析与取胜策略.md:45`）：

- 对手**上钩 commit** → 冻死半路 → 送不到。
- 对手**不上钩**停在上一节点等我走 → 他严格落后我 ≥1 节点；我 camp 到**自己交付死线的最后一帧**
  才出发，此刻他从身后出发**必然过了他自己的死线** → 也送不到。

成立前提 **C1（速度）**：我每帧速度 ≥ 他。他若用马更快，1 节点身位差可能被抹平——
**这正是冻结存在的意义**：把他冻住，速度优势兑不了现。所以对更快对手更要设卡。
（"最快路径 ≠ 最快到达"：同路对手用快马 1200/帧、短程马 1150/帧、疾行令 +30% 就更快，
ETA 引擎必须按对手"能用上的最好速度"算，见 §6。）

成立前提 **C2（鲜度线）**：见 §6.3。

## 2. 规则依据速查（任务书行号，实现时逐条核）

### 设卡（6.2）
- `SET_GUARD` 目标 = **当前所在节点**（:570,901）；S15 禁设（:911）。
- **处理帧数 4 帧**，**完成当帧不拦截、下一结算帧起才阻挡**（:917,922）。← 时序窗口来源
- 防守值 = `min(节点上限, 2 + 额外好果×2)`；额外好果 0/1/2（:918,919）。
- **防守上限**：普通 6、关键关隘 7（基础成本 1 好果）、宫门 S14=4、有障碍站点 5（:907-910）。
- **同时最多 2 张有效设卡**，超过移除本队最早那张（:921）。← 本策略"单张滚动"不触发上限
- 风化：普通/关隘<4 首次 30 帧后每 30 帧 -1；**关隘防御≥4 首次 45 帧**后每 30 帧（:930-932）。
- 防御降到 0 即失效移除，不能再增援激活（:936）。

### 冻结陷阱（8.2 + 6.3）
- `MOVING` 合法动作仅 `WAIT`/`MOVE到当前目标`/马/疾行令；**不能原路折返**（:1286）。
- 攻坚要求当前节点的相邻敌卡、且不是当前节点（:950）→ 冻在边上无法攻坚。
- 强通"从**当前节点**强行进入相邻阻挡节点"（:980,982）→ 冻在边上无法强通。
- 主车队之间无物理碰撞，可同帧同节点/同边；**普通移动是否受阻只看敌方有效设卡**（:223）。

### 强制通行（6.3.2，仅"对手停在节点上"时他才能用）
- 触发通行窗口 PASS（:981）；**总需求帧数 = 路线耗时 + 时间税**（:994）。
- 关键关隘时间税 `min(50,15+防×5)`（满防 45~50 帧）；普通 `min(40,10+防×5)`（满防 40）（:1000-1001）。
- 守方胜出→攻方失败休整 `min(8,max(3,ceil(税×0.25)))` 后重选（:991）。

### 小分队（3.4 / 6.4）
- 初始 **8 支人手**，每帧最多 1 个小分队动作（:520）。
- `SQUAD_REINFORCE` 2 支/次，己方有效卡 +2（不超上限）；`SQUAD_WEAKEN` 2 支/次，敌卡 -2、
  归 0 即不再阻挡（:529,530,1100,1101）。**不限距离**（:1107）。← 前压后仍能远程增援身后卡

### 窗口出牌（5.4，猜拳）
- 窗口固定 3 拍（:731）；出牌可在 空闲/等待/**移动中**/窗口争夺中提交（:767）
  ← 前压中仍能防守身后卡的 PASS 窗口。
- 牌与成本（:781-787）：`YAN_DIE`(1 文书) `QIANG_XING`(有马/疾行令免费,否则烧1马)
  `XIAN_GONG`(**鲜度≥80 且 1 好果/拍**) `BING_ZHENG`(1 护卫行动点) `ABSTAIN`(免费)。
- 猜拳表（:795-800）：**献贡赢 验牒+兵征，只输给强行**（全局最强单牌）。
- 3 拍胜点高者得权益，相同 = DRAW（双方休整3帧 + 对象 18 帧冷却，宫门 6 帧）（:802,817）。

### 交付与死线（4.5 / 3.2 / 7）
- 交付硬条件：位于 S15 + 已验核 + **好果>0 + 鲜度>0**（:667,668）。
- **鲜度品质分 = `floor(交付时剩余鲜度/100 × 180)`，封顶 180**（:1228,1333）。
- 鲜度衰减：停靠/等待/处理 0.05/帧（:453），移动按路型（pathing 里 0.045~0.07）。
- 鲜度首次低于阈值→1 好果转 1 坏果（:430）；**好果归 0 → 鲜度记 0 → 全货报废**（:443,444）。
- **悬赏 10（普通）/18（关隘），仅公开总分落后方攻破得分**（:1037,1038 + 分析文档:22）。← 拦截喂分小、可接受

## 3. 现有零件盘点（能直接复用的，别重造）

### `pathing.py`
- **`choke_nodes(state, src, dst)`** → 每条路线必经、排除端点的节点集 = **必经/公共节点**。✅ 直接用
- **`edge_frames_for_state(state, edge, move_per_frame)`** → 含天气的单边帧数，
  **`move_per_frame` 传高值即建模马匹**（快马≈1200、短程马≈1150）。✅ ETA 引擎基石
- `shortest_path/all_costs/path_frames/path_cost` → Dijkstra，但**成本是"鲜度优先、帧数次之"**。
  ⚠️ ETA 引擎要"理论最短**帧**"，需 frames-first 变体（见 G1）。
- `guard_max_defense` / `_guard_weathering_frames` → 设卡上限/风化帧，✅ 复用。

### `strategy/safety.py`
- **`must_rush(state)`** = `round + frames_to_terminal + RUSH_SAFETY_MARGIN(60) ≥ 600` = **路程线死线**。✅
- `frames_to_terminal(state)` / `_best_frames_from(src)` → 我方 ETA（含半路剩余边）。✅
- **`ahead_of_opponent(state, margin)`** → 我方 vs 对手到终点最短帧比较 = **基础 ETA 差**。✅
- `remaining_edge_frames(player)` → 半路玩家走完当前边的帧数。✅ 时序窗口用
- **`_can_opponent_set_guard_before_arrival`** → "对手能否抢先在我下一跳设卡"——
  **对称版就是"我能否抢先在对手下一跳设卡"**，G2 照抄改边。✅ 模板
- `hold_before_choke(state, next_node)` → **防守型**（对手蹲我方咽喉时我别进边）。
  ⚠️ 与本策略**进攻型 camp** 方向相反，别混用（见 §7 注意）。

### `strategy/combat.py`
- **`_propose_set_guard`**：已实现"在**当前节点**设卡"，且闸门已含 `_ahead_of_opponent` +
  `_is_opponent_choke` + 防御≥4 + 净值>阈值。✅ 位置对（设在脚下节点=我 camp 的节点）。
  ⚠️ 缺 **timing**（没等对手 commit，会过早设→落入"对手停节点能强通"的坏case）；
  ⚠️ 有 `me.total_score > opponent → return None` 领先闸（§4 G6 要放宽）。
- `_propose_squad_weaken`：**防守型**削敌卡（我被拦时）。✅ 保留
- **缺 `SQUAD_REINFORCE` proposer**（维持自家卡）——G3 新建。
- **`_choose_window_card` / `_mirror_break_card`**：已有自适应 + playerId 破对称 switcher。
  ⚠️ 默认序是 `(BING_ZHENG, YAN_DIE, XIAN_GONG)`，G7 改献贡优先。

### 优先级 & 编排

## 4. 改动清单（Gap 列表，按依赖排序）

> 记号：**[新建]** 全新代码；**[改造]** 动现有；**[旋钮]** 常量可回退。

### G1 [新建] ETA 引擎（frames-first + 马匹）— 一切触发的根
- `pathing.min_frames(state, src, dst, move_per_frame=BASE) -> int`：**纯帧数** Dijkstra
  （不含鲜度、不含任务绕行；含固定处理读条；含天气）。
- `pathing.min_frames_from(state, src, move_per_frame) -> dict[node,int]`：单源全图（多目标共用）。
- 对手速度取"**他能用上的最好速度**"：`opp_move_per_frame = f(对手当前 buff + 手里的马)`。
  保守可先用 `max(1200 if 对手有快马/在用马 else 1000)`；精细版在 §6.1。
- 我方对称：`me_move_per_frame`（我在用的 buff）。

### G2 [新建] 拦截控制器（camp + 上边瞬间设卡冻结）
新增 `InterceptStrategy`（或并入 combat，见 §7 权衡）。每帧：
1. 用 ETA 引擎定位"**对手到终点路径上、我能先到的第一个必经节点 N**"（§6.2）。
2. 若我已站在 N（`current_node==N`、IDLE）：
   - **camp 判定**：只要 `not must_rush` 且 N 是拦截点 → 不离开 N（压制 delivery 的走位，见 §7）。
   - **set-on-commit**：仅当"对手已 commit 到进入 N 的边、且他离 N 还有 ≥ `GUARD_SETUP_FRAMES+安全` 帧"
     （§6.4 `freeze_window_open`）→ 发 `SET_GUARD@N`（投满，见 G6/§6.5）。
     否则**不设**（早设=坏 case），继续 camp。
3. 若我还没到 N：交给 delivery 正常走位抢跑（拦截控制器不发 MOVE，避免与 delivery 抢主车队额度）。

### G3 [新建] `SQUAD_REINFORCE` proposer（维持自家卡）
- 己方在 N 有有效卡、且 `defense < 目标值`（被削或风化）、且 `squad_available≥2` → 发 `SQUAD_REINFORCE@N`。
- 优先级介于 `SQUAD_WEAKEN(128)` 与 `SQUAD_SCOUT(127)` 之间（拦截局增援 > 探路）。
- **不限距离**（:1107）→ 前压到下一节点后仍能远程增援身后卡。
- 旋钮 `REINFORCE_SQUAD_FLOOR`：留几支不增援（防一张卡吃光人手，下张无兵）。

### G4 [改造] 交付死线 = `min(路程线, 鲜度线)`

## 5. 核心触发时序（逐帧状态机，拦截控制器视角）

```
每帧 inquire →
  if me.delivered/retired: 无拦截
  elif delivery_deadline_hit(state):        # G4 最高闸
        弃拦；不 camp、不设卡；delivery 直冲 S15
  elif opponent_cannot_finish(state):       # G5 对手已判死
        弃拦；delivery 直冲 S15（顺路 slack 够可做任务）
  else:
        N = 我能先到的对手必经节点（G2/§6.2）
        if N is None: 无拦截（我没领先/无咽喉）→ delivery 正常抢跑
        elif me at N (IDLE):
              camp（压制 delivery 走位，§7）
              if freeze_window_open(state, N):   # §6.4：对手 commit 进 N 的边 & 帧够
                    SET_GUARD@N 投满（G6/§6.5）
              维持：SQUAD_REINFORCE@已设卡（G3），被削则补
        else:  # 还没到 N
              delivery 正常抢跑到 N（拦截控制器不发 MOVE）
  # 前压：对手破卡/风化后越过 N 继续走 → 下一帧 N 自动更新为下一个必经节点（滚动单张）
  # 窗口：任意帧有我方在场 PASS/TASK/... 窗口 → combat 出牌（默认三联献贡，G7）
```

对手一旦冻在 N 前的边上：我方**前压到下一必经节点 N'**（delivery 走位），
远程 `SQUAD_REINFORCE` 维持 N 的卡（不限距离），到 N' 后重复 camp+set-on-commit。**滚动单张卡。**

## 6. 关键公式

### 6.1 ETA（理论最短帧，含马）
```
me_eta(node)  = min_frames(state, me_pos,  node, me_move_per_frame)   (+ 半路剩余边帧)
opp_eta(node) = min_frames(state, opp_pos, node, opp_move_per_frame)  (+ 半路剩余边帧)
opp_move_per_frame = 1200 若对手在用/持有快马；1150 短程马；否则 1000（保守取其能达到的最大）
```
半路剩余边帧复用 `safety.remaining_edge_frames`。

### 6.2 拦截点 N（我能先到的对手必经节点）
```
chokes = ∪_{terminal} choke_nodes(state, opp_pos, terminal)     # 对手视角的必经节点
候选 = { c ∈ chokes : c 在对手到终点的最短路径上, 且 me_eta(c) + GUARD_SETUP ≤ opp_eta(c) }
N = 候选中 opp_eta 最小者（对手最先撞上的那个我能先到的咽喉）
若候选空 → N=None（我没领先，或无真咽喉）→ 不拦截，纯抢跑（R2 的 C1 会在死线兜底）
```

### 6.3 鲜度线 `freshness_deadline_hit`
不是硬帧数线，是"品质/合法性预算"。触发（任一）：
```
(a) 预计交付时鲜度 ≤ FRESH_MIN_AT_DELIVER(旋钮, 如 5)         # 逼近报废
(b) 好果 - 已承诺卡/牌好果 ≤ GOOD_MIN_AT_DELIVER(旋钮, 如 1)  # 逼近好果归零悬崖
(c) 继续 camp N 帧带来的鲜度品质分损失(≈ N×0.05×1.8) > 拦截边际收益  # 软权衡, 可后置
```
预计交付鲜度 = `me.freshness - (到S15路径鲜度损耗估计, 用 path_cost 的鲜度分量)`。
实务：纯 camp 很便宜（0.05/帧），通常**路程线先到**；(b) 好果侧在多设卡/多出牌时先崩。

### 6.4 冻结窗口 `freeze_window_open(state, N)`
```
对手 next_node == N 且 state==MOVING（已 commit 上边）
且 remaining_edge_frames(opp) ≥ GUARD_SETUP_FRAMES(4) + FREEZE_SAFETY(旋钮, 如 2)
→ True（设卡能在他到达前生效 = 冻死）
（对手停在 N 的相邻节点未上边 → False，早设会让他停在节点上强通，别设，继续 camp）
```

### 6.5 设卡投入（好果预算）
```
目标防御 = guard_max_defense(N)   # 关隘 7 / 普通 6
基础成本 = 关隘/宫门 1 好果, 否则 0；额外好果 extra∈{2,1,0}
选最大 extra 使 (my_good - 基础 - extra) ≥ GOOD_MIN_AT_DELIVER(交付好果底线)
defense = min(上限, 2 + extra×2)   # set 到 6，关隘再靠 REINFORCE +1 到 7
```

### 6.6 对手判死 `opponent_cannot_finish`
```
opp_finish = opp_min_frames_to_finish(最好速度)
             + Σ 时间税(我方仍挡在他前面的有效卡)          # 每张关隘满防 ≈45~50
             + 验核/交付余量(旋钮, 如 20)
return state.round + opp_finish > state.duration_round
```

1. `min_frames`：直线图帧数正确；含处理站计入读条；马匹 `move_per_frame` 变大→帧数变小。
2. `min_frames` vs `shortest_path`：帧数线可能选不同于鲜度线的路（断言二者可分歧）。
3. `interception_node`：我领先→返回对手最先撞上的咽喉；我落后→None；无咽喉→None。
4. `freeze_window_open`：对手 MOVING+next==N+剩余边帧≥6 → True；停在相邻节点未上边 → False；剩余边帧<6 → False。
5. `_propose_set_guard` timing：`freeze_window_open` False 时不设卡（即使其他闸都过）。
6. `_propose_set_guard` 领先闸放宽：我方领先 + 冻结窗口开 → 仍设卡（G6）。
7. `_propose_squad_reinforce`：己方卡被削到 <目标 + 有兵 → 发 REINFORCE；卡满/无兵 → None；远程（不在 N）也能发。
8. `freshness_deadline_hit`：好果逼近底线 → True；鲜度逼近 0 → True；充裕 → False。
9. `opponent_cannot_finish`：对手剩余帧 < 需求 → True；充裕 → False；含我方卡时间税加成。
10. `delivery_deadline_hit` → delivery `_pick_move_target` 在拦截点仍返回目标（弃 camp 直冲），不自冻。
11. camp：`interception_node==cur 且 not deadline` → `_pick_move_target` 返回 ""（原地）。
12. 窗口默认献贡：无对手历史 + 鲜度≥80 + 好果>1 → 首选 `XIAN_GONG`；鲜度<80 → 退化不选献贡。
13. 铁律不回归：拦截/camp/设卡任何分支都不得让某帧抛异常或缺 action（沿用 `test_runtime_ironlaw`）。

## 9. 回退旋钮 & 风险登记

### 旋钮（常量，出问题逐个回退）
| 旋钮 | 位置 | 默认 | 作用 |
|---|---|---|---|
| `FREEZE_SAFETY` | combat/safety | 2 | 冻结窗口安全余量；调大更保守（少设卡、少白设） |
| `GOOD_MIN_AT_DELIVER` | safety | 1 | 交付好果底线；调大=少烧好果给卡/牌，护交付分 |
| `FRESH_MIN_AT_DELIVER` | safety | 5 | 交付鲜度底线 |
| `REINFORCE_SQUAD_FLOOR` | combat | 2 | 留几支不增援（防一张卡吃光人手） |
| `GUARD_GOOD_FLOOR` | combat | (降/动态) | 旧硬地板，保留可一键回到 90 = 近乎不设卡 |
| `ENDGAME_MARGIN`/`RUSH_SAFETY_MARGIN` | economy/safety | 40/60 | 死线余量，已存在 |

### 风险登记
- **R-自冻（最高）**：任何主动 WAIT/camp 类机制都有自冻史（hold 36 帧、蹲守 25 帧，已删）。
  本策略 camp 必须被 `delivery_deadline_hit` 硬闸兜住，回归里"未送达局=0"是**发布闸**。
- **R-镜像**：同源 ~775 对手也会拦我 → 走廊对锁 / 窗口连平 0:0。用户决定**暂不做**额外 playerId 破对称，
  沿用已实现 switcher；残余风险接受（与 P4h ② 一致）。触发即回退到"纯送达+死线"档。
- **R-强行专克献贡**：对手一路 `QIANG_XING`（有马免费）克三联献贡 → 靠现有 `_opponent_*_tendency`
  自适应兜；兜不住则该窗口输，非致命。
- **R-时序窗口太紧**：某些短边 `freeze_window_open` 恒 False → 那个咽喉设不了卡，自动 fall through
  到"前压下一咽喉 / 死线送达"，不致命（引擎自纠）。**落地前需实测 S08/S09→S10→S11 各边帧数确认余量**。
- **R-同路任务被抢**：拦截期间 camp 可能让 economy 少抢任务 → 任务分掉档（近期败因）。
  靠 §6 的 slack 闸（`slack ≥ 设卡读条+往返` 才做任务）平衡；需回归盯 raw 任务分。
