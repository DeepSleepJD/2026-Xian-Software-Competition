# 我方客户端架构设计

> 2026-07-02 定稿并经负责人批准（"认可，按此实施"）。本文档是 P1 骨架搭建及后续三人协作的接口契约基准。
> 战略背景见 `docs/比赛分析与取胜策略.md`；协议细节以 `refs/debug-kit-v1/` 下任务书与通信协议为准。

## 一、设计目标

1. **永不退赛**：每帧必发 action（空 `actions:[]` 也是心跳）、`action.round == inquire.round`、500ms 内必回——由独立铁律层保证，与策略代码隔离。
2. **三人并行开发零冲突**：策略模块间不互相依赖，公共接口只有 GameState（读）与 Intent（写）。
3. **可离线测试**：除网络层外全部可用录制的 JSON 消息做单元测试。
4. 硬约束：Python 3.12 stdlib 零第三方依赖；不写死 playerId/host/port/阵营/地图，一切以 start/inquire 下发为准。

## 二、目录结构

```
client/                     # 我方参赛客户端（全新包，独立于官方参考件）
  lychee/
    net.py                  # TCP 连接 + 5位十进制长度前缀分帧（移植官方 framing.py，已验证可靠）
    protocol.py             # start/inquire JSON → 类型化数据结构；action 构造 + 合法性预检
    state.py                # GameState 世界模型：地图、双方队伍、任务、资源、天气、设卡、事件
    pathing.py              # 图结构/最短路/路线规划（基于 start 下发的地图，支持换图变体）
    strategy/               # ★ 三人并行开发的主战场
      __init__.py           #   Strategy 基类：propose(state) -> list[Intent]
      delivery.py           #   主线走位/处理/验核/交付状态机          （P1，同学A）
      economy.py            #   任务估值/资源领取/鲜度阈值管理          （P2/P3，同学B）
      combat.py             #   窗口出牌/设卡/攻坚/强通/绕行            （P4，同学C）
    arbiter.py              # 意图仲裁：各策略 Intent 按优先级合并去冲突 → 每帧最终 actions
    runtime.py              # 主循环 + 铁律兜底（心跳/round匹配/500ms看门狗/异常不外泄）
    recorder.py             # 每帧收发落盘 jsonl（复盘 + 回归测试数据源）
  main.py                   # 入口，参数 <playerId> <host> <port>
  start.sh                  # 比赛提交要求的启动脚本（同参数）
  tests/
```

## 三、核心机制

### 1. 数据流（每帧）

```
inquire JSON → protocol 解析 → state 更新 GameState
  → 各 strategy.propose(state) 产出 list[Intent]
  → arbiter 按优先级仲裁合并 → protocol 构造 actions + 合法性预检
  → net 发送。全程由 runtime 包裹：任何一步异常/超时 → 兜底发空心跳。
```

### 2. 接口契约（冻结点，改动需三人同步）

- **GameState**：策略层的唯一输入。字段在 P1 首版定稿（覆盖 start/inquire 下发的全部信息 + 少量派生量如"到各节点最短路"）。
- **Intent**：策略层的唯一输出。带 `kind`（意图类型）、`priority`（仲裁优先级）、`actions`（候选动作）。策略模块不直接发包、不互相调用。
- 接口一旦冻结，三人分头改各自 strategy 文件即可，git 无踩踏。

### 3. 铁律层（runtime.py，写完锁定）

- 每帧必回：策略层抛异常、算超时（预算 ~400ms 留余量）→ 发 `actions:[]` 心跳。
- `action.round` 恒等于当前 `inquire.round`。
- 断连/EOF 优雅退出；`error`/`over` 消息正确处理。
- 违规监控：读 `events[]`/`actionResults[]`，非法动作累计告警（前 5 次免罚，之后 -1/次）。

### 4. 可测试性

- state/pathing/strategy/arbiter 均不碰 socket → 用 `refs/debug-kit-v1/start消息.json`、`inquire消息.json` 及 recorder 录制的真实对局帧做单测。
- 集成测试：`python tools/run_match.py --client-cmd "python client/main.py {player_id} {host} {port}"` 打官方 demo。
- 每局 recorder 产出的 jsonl 即回归数据。
