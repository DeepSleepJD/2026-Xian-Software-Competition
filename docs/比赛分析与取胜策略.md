# 《一骑红尘：荔枝争运战》比赛分析与取胜策略

> 归档日期：2026-07-02。基于对任务书（1534 行）、通信协议 V3（2710 行）、map_config.json、调测包脚本的完整阅读分析。
> 原始资料位置见文末"资料索引"。

## 一、比赛本质

- 双人（红 vs 蓝）对称对抗，**600 结算帧**内把荔枝从 S01 岭南果园运到 S15 兴庆宫，**最终总分高者胜**。
- 提交物：AI 客户端 ZIP（根目录含可执行 `start.sh`，接收 `<playerId> <host> <port>` 三参数），Linux 运行环境（Python 3.12.9 / Go 1.22.5 / JDK21 / Node 16 / GCC12 可用），**禁止现场安装依赖、禁止联网**。
- 通信：TCP，5 位十进制长度前缀 + UTF-8 JSON body；流程 `registration → start → ready → inquire/action 循环 → over`；每帧 **500ms** 内提交 action。
- 平台积分：胜 3 / 负 0 / 平分决胜 3-1（依次比鲜度→好果→惩罚分）/ 完全平局 1-1；异常参赛（离线/身份无效）直接 0 分。

## 二、得分结构（取胜核心）

| 分项 | 上限 | 公式 / 关键规则 |
|---|---:|---|
| 送达基础分 | 240 | `min(240, 120 + floor(任务基础分×4/3))`；**必须交付**；任务分≥90 拿满 |
| 皇榜任务分 | 180 | 任务累计 + 里程碑（60/90/110 → 累计+15/+35/+50） |
| 好果数量分 | 180 | `floor(好果/100×180)`，每篓 ≈ **1.8 分** |
| 鲜度品质分 | 180 | `floor(鲜度/100×180)`，每点 ≈ **1.8 分** |
| 用时分 | 69 | `floor((600-交付帧)/600×70) × min(任务分,90)/90`，每帧仅 ≈0.117 分 |
| 破关悬赏分 | 100 | **只有公开总分落后方攻破设卡才得悬赏分**（追赶机制） |
| 惩罚 | -50 | 非法动作前 5 次免罚后每次 -1（上限20）；交付后违规每次 -5（上限30） |

未交付时：送达/好果/鲜度/用时全为 0，任务封顶 80、悬赏封顶 25 → **总分上限约 105**。

### 四条决定性洞察

1. **不交付 = 必输**；连续 60 帧缺动作 = 退赛判负。客户端稳定性（拆包正确、每帧心跳、永不卡死）是第一胜负手。
2. **任务基础分 90 是最大杠杆**：0→90 实际撬动 ≈ 90(任务)+35(里程碑)+120(送达补满)+~20(用时恢复) ≈ **265 分**。三个 30 分任务即达 90。进阶：110（+35）、130（任务满 180）。
3. **时间不值钱，鲜度/好果值钱**：宫门验核（S14）最早第 390 帧才开放（RUSH 阶段，450 帧必开），无加速全程仅需 ~410 帧，时间不是瓶颈。慢 50 帧丢 ~6 分，1 个冰鉴 = +10 鲜度 = **+18 分**（全图仅 3 个：S03/S06/S07）。前 390 帧应刷任务、抢资源、保鲜度。
4. **鲜度阈值管理**：鲜度每**首次**跌破 90/80/70/…/10 触发 1 篓好果转坏（双重损失 ~3.6 分）。冰鉴要在临近跌破阈值前用。平分决胜第一项也是鲜度。

## 三、路线定量分析（基础图，换图时需以 start 下发重算）

三条主干（到 S09 汇合，无加速）：

| 路线 | 移动帧 | 处理帧 | 鲜度损耗/帧 | 备注 |
|---|---:|---:|---|---|
| 水路 S01→S02→S04→S05→S09 | ≈184 | 4+7+6=17 | 0.045 最低 | 最快最省鲜，怕暴雨（处理+4、移动×1.35） |
| 官道 S01→S02→S03→S07→S09 | ≈214 | 4 | 0.055 | S03 有 T01+冰鉴+过所+情报 |
| 山路 S01→S06→S08→S10 | ≈246 | 0 | 0.07 最高 | 慢，怕山雾，障碍多发 |

- 移动结算：到站需求 = `ceil(距离×系数)`（ROAD 1380 / WATER 1250 / MOUNTAIN 1780 / BRANCH 1550）；每帧移动量 = `floor(基础量×1000/天气倍率)`，基础量：无加速 1000 / 短程马 1150(14帧) / 快马 1200(20帧) / 疾行令 1300(15帧，互斥)。
- S09 之后单通道：S10(关键关隘)→S11(处理5)→S12→S13(处理5)→S14(验核6)→S15，约 160 帧。**S10–S14 是必经窄路 = 设卡对抗主战场**。
- 水路全程 ≈ 410 帧，富余 ~180 帧可绕路做任务。
- 顺路任务密集区：S04/S05(T08)、S09(T06/T13)、S10/S11(T02/T11/T14/T12)、S13(T12/T13)。30 分任务：T01/T02/T04/T06/T08/T11；15 分：T12/T13/T14。
- **提效**：探路标记（情报资源，距离≤15；或小分队探路 1 人手×8）处理帧 -3（最低 2），5 个固定处理点全覆盖省 ~15 帧。

## 四、关键机制备忘

- **窗口争夺**：3 拍出牌。克制环：验牒>强行、强行>献贡、献贡>验牒&兵争、兵争>验牒&强行。成本：验牒=1文书、强行=1马(有马buff免费)、献贡=鲜度≥80+1好果、兵争=1护卫点(初始4)。**弃权零成本零惩罚**——打不过就弃权。
- **设卡**：每队最多 2 个有效，防守值 `min(上限, 2+额外好果×2)`，30 帧风化-1。存活 30 帧生成悬赏 → **领先时别贪悬赏，落后时是翻盘工具**。
- **突破**：攻坚（好果2点/坏果3点攻坚值，失败休整5帧）、强制通行（时间税 = min 公式按防守值，障碍固定 8 帧；同节点不可重复强通）、小分队削弱(-2)。
- **协议红线**：5 位长度前缀拆包（粘包/半包/UTF-8 跨包）；`action.round == inquire.round`；每帧必发（空 `actions:[]` 是有效心跳）；**不得写死 playerId/host/port/阵营/地图**（比赛会换地图变体，一切以 start/inquire 下发为准）。
- **天气**：4 次×60 帧，提前 30 帧预告（80-120/200-240/320-360/440-480 窗口）。酷暑全图鲜度×1.5（停下也扣）、暴雨水路、山雾山路。
- **交付时机**：RUSH 后先评估剩余任务价值 vs 拖延成本（每帧 ≈0.2 分），通常做完附近高价值任务再交付，但留 600 帧硬截止和对手设卡的安全余量。
- **非法动作前 5 次免罚**，业务拒绝不计非法；以 `events[]`/`actionResults[]` 为准修正策略。
