## 一、皇榜任务规则要点（任务书 5.1-5.3）

- 处理任务发 `CLAIM_TASK` + `taskId`（来自 `inquire.tasks[].taskId`）；**必须停在任务目标节点**。
  例外：T04 清障任务可在目标障碍节点**或相邻节点**处理（完成同时清障、人不动）。
- 同一时间只能处理 1 个任务实例；完成后重复处理被拒（业务拒绝不罚）。
- T06 争马换乘：启动时**消耗 1 个快马或短程马**。
- T04 注意:目标障碍被人用普通清障（CLEAR/小分队）清掉 → 该 T04 直接失败不补刷。
- 任务池最多 18 活跃 / 同时可处理 10；`expireRound` 后失效。
- 对手同帧抢同一任务 → 触发窗口争夺（P2 先弃权让出，P4 再博弈）；
  `protectionPlayerId` 非本方时短期别碰，`ownerPlayerId` 非 0 且非本方别碰。

## 三、EconomyStrategy 设计草案

- 新文件 `client/lychee/strategy/economy.py`，冻结契约不动（只读 GameState、产 Intent）。
- **优先级**：冰鉴使用 120 > 任务/资源领取与赶路 110 > delivery 100。
  arbiter 已保证主车队动作同帧只出 1 个（CLAIM_TASK/CLAIM_RESOURCE/USE_RESOURCE/MOVE 同类）。
- **活跃窗口**：NORMAL 阶段 && 未验核 && task_score < 90 时做任务；
  一到 RUSH 或拿满 90 → economy 闭嘴，delivery 接管直奔宫门。
- **目标选择**（每帧重算，贪心）：候选 = 活跃未完成、无对方归属/保护、
  round + 路程 + 读条 ≤ expireRound 的任务；成本 = 绕路增量帧
  （path(cur→任务节点)+读条+path(任务节点→宫门) − path(cur→宫门)）；
  取 value/(cost+1) 最大者；到达目标节点后发 CLAIM_TASK。
- **冰鉴**：领取=顺路或小绕（S03 绕路价值≈+18分−绕路鲜度损耗，斟酌）；
  使用=停靠时 freshness ≤ 下一个十位阈值+2 即用（每首次跌破 90/80/70…有 1 好果转坏，
  双重损失 ~3.6 分；出发上长边前要预判途中跨阈值，提前用）。
- **暂缓**（P3 再做）：INTEL 探路减时（时间不值钱，~15帧≈1.75分）、马类加速、
  任务分 110/130 冲刺、窗口出牌。
- **防守细节**：读条中/移动中 propose 返回 []（delivery 同款守则）；
  CLAIM_* 被拒（OBJECT_BUSY 等）下帧重试或换目标；同帧对手抢任务触发窗口 → 弃权（不出牌即弃权，零成本）。
